# Куки: разбор, сборка, подпись и хранилище

`tnt-cookie` работает с куками как с форматом: разбирает заголовок `Cookie`
запроса и чужой `Set-Cookie`, собирает `Set-Cookie` со строгими
умолчаниями, подписывает значение и хранит чужие куки для исходящих
запросов.

```lua
local cookie = require('tnt.cookie')

cookie.configure({ key = env.required('COOKIE_KEY') })
response.headers['set-cookie'] = cookie.set('sid', cookie.sign('42'), { max_age = 3600 })
local sid, err = cookie.unsign(cookie.parse(request.headers['cookie']).sid)   -- '42' либо nil, причина
```

Зависит от `tnt-validate` (проверка настроек), `tnt-hash` (HMAC-SHA256
и сверка за постоянное время), `tnt-log` (журнал пропущенных кусков
заголовка), `tnt-clock` (стенные часы сроков в хранилище) и `tnt-external`
(подмена часов и загрузки libpsl в проверках). Необязательно — системная
библиотека libpsl: из неё хранилище берёт список публичных суффиксов.
Ключ в примерах берётся из окружения через
[`tnt-env`](https://github.com/tnt-skein/tnt-env), но пакету всё равно,
откуда он пришёл.

## Зачем пакет

Кука — единственное место, куда браузер сам кладёт данные и сам их
возвращает. На этом стоят сессии, и на этом же ломаются приложения: кука
без нужных пометок читается чужим сценарием на странице, уезжает на чужой
сайт вместе с запросом или переписывается тем, кто сидит за клавиатурой.

Куки нужны на обеих сторонах HTTP: сервер читает их из запроса и ставит
в ответ, клиент хранит чужие и отправляет обратно. И там и там это строки
заголовков, и ошибиться в них легко: разбор падает на одной чужой куке
и отключает всё приложение, собранный руками `Set-Cookie` забывает
`HttpOnly`, значение `x; admin=1` приезжает обратно двумя куками, подпись
сверяется обычным `==` и подбирается по времени ответа. Пакет держит эту
работу в одном месте:

- **Разбор `Cookie`** не падает на чужом мусоре: негодный кусок
  пропускается, остальные доезжают.
- **Сборка `Set-Cookie`** ставит `HttpOnly`, `Secure` и `SameSite=Lax`,
  пока их не выключат словом, держит обещания приставок `__Host-`
  и `__Secure-` и отвергает недопустимые знаки, а не вырезает их молча.
- **Подпись** — HMAC-SHA256 со сверкой за постоянное время.
- **Разбор чужого `Set-Cookie`** — по алгоритму RFC 6265 (5.2), с датами
  во всех трёх видах, которые шлют серверы.
- **Хранилище** для исходящих запросов отбирает куки по домену, пути,
  сроку и `Secure` по правилам RFC 6265 (5.3 и 5.4), не ставит куку
  на публичный суффикс вроде `co.uk`, не берёт из открытого канала
  то, что могло бы подменить защищённую куку, и не верит приставке,
  за которой нет обещанного (RFC 6265bis, 5.7).

Пакет работает со строками заголовков и в договор о запросе не лезет:
разложить разобранное по полям запроса — работа того, кто принимает
запрос.

## Как пользоваться

| Вызов | Что делает |
|---|---|
| `cookie.parse(text)` | разбирает заголовок `Cookie` запроса в таблицу «имя → значение» |
| `cookie.set(name, value, opts)` | собирает `Set-Cookie`; отказ — `nil, err` |
| `cookie.expire(name, opts)` | собирает `Set-Cookie`, который велит браузеру забыть куку |
| `cookie.sign(value, key)` | подписывает значение; без ключа бросает |
| `cookie.unsign(text, key)` | снимает подпись, проверив её; отказ — `nil, err` |
| `cookie.parse_set(text)` | разбирает чужой `Set-Cookie`; отказ — `nil, err` |
| `cookie.jar()` | новое пустое хранилище кук: `put`, `header_for`, `size`, `clear` |
| `cookie.configure(opts)` | настраивает общий набор; негодная настройка бросает |
| `cookie.new(opts)` | отдельный набор со своими умолчаниями |
| `cookie.default()` | общий набор |
| `cookie.status()` | действующие настройки без ключа |

### Заголовок запроса: `parse`

`cookie.parse(text)` превращает значение заголовка `Cookie` в таблицу
«имя → значение»:

```lua
cookie.parse('sid=abc; theme="dark"')               --> { sid = 'abc', theme = 'dark' }
cookie.parse('  sid = a b  ')                        --> { sid = 'a b' }
cookie.parse('sid=свой; sid=чужой')                  --> { sid = 'свой' }
cookie.parse('junk; =empty; bad name=1; sid=abc')    --> { sid = 'abc' }
cookie.parse(nil)                                    --> {}
```

- **Отказа у разбора нет.** Заголовок присылает клиент — браузер, прокси,
  тот, кто собрал запрос руками, — и одна негодная кука не должна
  отключать всё приложение. Кусок без имени или с именем, непохожим
  на лексему HTTP, пропускается и отмечается в журнале `tnt-log` под
  именем `tnt.cookie` на уровне `debug` — без имени и без значения:
  в значении ездит опознаватель сессии. Не строка вместо заголовка — пустая
  таблица.
- **Из двух кук с одним именем берётся первая.** Браузер шлёт их от самого
  точного пути к самому общему (RFC 6265, 5.4), и вторая с тем же именем —
  либо кука соседнего пути, либо подложенная с поддомена в расчёте на то,
  что разбор возьмёт последнюю.
- **Пробелы по краям снимаются, внутри остаются**, кавычки вокруг значения
  снимаются (см. «Чем пришлось поступиться»).

### Кука в ответ: `set`

`cookie.set(name, value, opts)` собирает значение заголовка `Set-Cookie`
либо отказывает парой `nil, err`:

```lua
cookie.set('sid', 'abc')
--> 'sid=abc; Path=/; SameSite=Lax; Secure; HttpOnly'

cookie.set('theme', 'dark', { max_age = 86400, http_only = false })
--> 'theme=dark; Max-Age=86400; Path=/; SameSite=Lax; Secure'

cookie.set('sid', 'x; admin=1')
--> nil, 'в значении куки недопустим знак «;» на месте 2: заголовок разделяют пробел, кавычка,
--  запятая, точка с запятой и обратная косая, и внутри значения их быть не может'
```

Настройки одной куки:

| Настройка | Умолчание | Что пишет |
|---|---|---|
| `path` | `'/'` | `Path`; начинается с `/`, печатные знаки US-ASCII без `;` |
| `domain` | нет | `Domain`; латинские буквы, цифры, дефисы и точки, хотя бы одна точка |
| `expires` | нет | `Expires` — секунды от начала эпохи, целое, в 1601—9999 годах |
| `max_age` | нет | `Max-Age` — целое число секунд, ноль и меньше значат «забудь» |
| `secure` | `true` | `Secure` |
| `http_only` | `true` | `HttpOnly` |
| `same_site` | `'lax'` | `SameSite`: `'strict'`, `'lax'`, `'none'`; `'off'` — без атрибута |
| `partitioned` | `false` | `Partitioned` |

Атрибуты идут всегда в одном порядке — `Expires`, `Max-Age`, `Domain`,
`Path`, `SameSite`, `Secure`, `HttpOnly`, `Partitioned`: заголовок попадает
и в проверки, и в журнал, и один и тот же ответ должен выглядеть
одинаково.

Имя — лексема HTTP: буквы, цифры и знаки ``!#$%&'*+-.^_`|~``. Значение —
печатные знаки US-ASCII без пробела, кавычки, запятой, точки с запятой
и обратной косой; пустое значение законно. Недопустимый знак — отказ
с его местом, а не молчаливая чистка: урезанное значение ушло бы клиенту
целым с виду, и разбираться с ним пришлось бы тому, кто его получил.
Знак вне печатных US-ASCII отказ называет байтом, чтобы не разорвать
запись журнала:

```lua
cookie.set('sid', 'привет')
--> nil, 'в значении куки недопустим байт 208 на месте 1: …'
```

Текст с пробелами, кириллицей или разметкой пакет не кодирует — его
кодируют до сборки, например в base64url.

Остальные отказы сборки:

```lua
cookie.set('sid', 'x', { path = 'admin' })
--> nil, 'путь куки должен начинаться с «/»: иначе браузер подставит путь запроса, и кука уедет не туда, куда её ставили'
cookie.set('sid', 'x', { domain = 'com' })
--> nil, 'домен куки должен содержать точку: домен из одного слова — это зона целиком, и куку на неё не поставит ни один браузер'
cookie.set('sid', 'x', { max_age = 1.5 })
--> nil, 'время жизни куки max_age должно задаваться целым числом секунд'
cookie.set('sid', 'x', { expires = 253402300800 })
--> nil, 'срок куки expires должен лежать между -11644473600 и 253402300799 — в 1601—9999 годах,
--  а не 253402300800: другой год не записать датой, которую прочтёт браузер'
cookie.set('sid', 'x', { same_site = 'maybe' })
--> nil, 'признак SameSite бывает strict, lax, none или off, а не «maybe»'
```

Срок вне 1601—9999 годов отвергается потому, что такую дату браузер
не прочтёт и пропустит молча — кука, которой назначили срок, прожила бы
до закрытия браузера.

### Умолчания строгие

`HttpOnly`, `Secure` и `SameSite=Lax` стоят, пока их не выключат словом.
Причина в каждом случае своя:

| Пометка | Что без неё |
|---|---|
| `HttpOnly` | куку читает любой сценарий на странице, включая чужой |
| `Secure` | кука уходит по открытому каналу, и её видит и переписывает всякий, кто видит сеть |
| `SameSite=Lax` | кука уезжает вместе с запросом, отправленным с чужого сайта, — это и есть CSRF |

`Lax`, а не `Strict`: `Strict` роняет переход по ссылке из письма, и его
снимают целиком, вместе с защитой. Выключается каждая пометка своим
словом:

```lua
cookie.set('sid', 'abc', { secure = false, http_only = false, same_site = 'off' })
--> 'sid=abc; Path=/'
```

Путь по умолчанию — `/`: кука видна всему узлу, иначе она не доедет
до соседнего маршрута. Домена по умолчанию нет: кука без `Domain`
принадлежит ровно поставившему её узлу, а с `Domain` уезжает на все
поддомены разом.

Обещания, которые нельзя выполнить, пакет не собирает. `SameSite=None`
значит «прикладывать к запросам с чужих сайтов», и браузеры отвергают
такую куку без `Secure`; `Partitioned` вне HTTPS ничего не разделяет:

```lua
cookie.set('sid', 'x', { same_site = 'none', secure = false })
--> nil, 'кука с SameSite=none ходит на чужие сайты и потому обязана быть secure = true'
cookie.set('sid', 'x', { partitioned = true, secure = false })
--> nil, 'кука с признаком partitioned обязана быть secure = true'
cookie.set('widget', 'x', { same_site = 'none', partitioned = true })
--> 'widget=x; Path=/; SameSite=None; Secure; HttpOnly; Partitioned'
```

### Приставки `__Host-` и `__Secure-`

Приставка — обещание, вписанное в имя (RFC 6265bis, 4.1.3): `__Host-`
значит «кука одного узла, на весь узел и только по HTTPS», `__Secure-` —
«только по HTTPS». Браузер отвергает куку, обещание не выполнившую,
и делает это молча: сессия просто не заводится. Поэтому несостыковка
ловится при сборке:

```lua
cookie.set('__Host-sid', 'abc')
--> '__Host-sid=abc; Path=/; SameSite=Lax; Secure; HttpOnly'
cookie.set('__Host-sid', 'abc', { domain = 'example.org' })
--> nil, 'кука с приставкой __Host- принадлежит одному узлу: домен задавать нельзя'
cookie.set('__Host-sid', 'abc', { path = '/admin' })
--> nil, 'кука с приставкой __Host- видна на всём узле: путь обязан быть «/»'
cookie.set('__Secure-sid', 'abc', { secure = false })
--> nil, 'кука с приставкой __Secure- ставится только по HTTPS: нужен secure = true'
cookie.set('__HOST-sid', 'abc', { domain = 'example.org' })
--> nil, 'кука с приставкой __Host- принадлежит одному узлу: домен задавать нельзя'
```

Приставка узнаётся без регистра: браузер читает `__HOST-sid` так же, как
`__Host-sid` (RFC 6265bis, 5.4), и такую куку без обещанного выбросит
так же молча. Имя, только похожее на приставку (`__Hostile`), обещаний
не несёт. Чужие куки с приставкой хранилище сверяет теми же правилами
(см. «Приставки в хранилище»).

### Забыть куку: `expire`

Удаление куки — та же её постановка, только с истёкшим сроком:

```lua
cookie.expire('sid')
--> 'sid=; Expires=Thu, 01 Jan 1970 00:00:00 GMT; Max-Age=0; Path=/; SameSite=Lax; Secure; HttpOnly'

cookie.expire('sid', { path = '/admin' })
--> 'sid=; Expires=Thu, 01 Jan 1970 00:00:00 GMT; Max-Age=0; Path=/admin; SameSite=Lax; Secure; HttpOnly'
```

Путь и домен обязаны совпасть с теми, с которыми куку ставили: браузер
различает куки по тройке «имя, домен, путь», и `Path=/` не удалит куку,
поставленную на `/admin`. И `Max-Age`, и `Expires` — первый понимают все
нынешние браузеры, второй нужен тем, кто `Max-Age` не знает.

### Настройки пакета: `configure`, `new`, `status`

Умолчания каждой куки и ключ подписи задаются настройкой:

```lua
cookie.configure({
    key = env.required('COOKIE_KEY'),
    domain = 'example.org',
    same_site = 'strict',
})

cookie.set('sid', 'abc')
--> 'sid=abc; Domain=example.org; Path=/; SameSite=Strict; Secure; HttpOnly'
cookie.set('sid', 'abc', { domain = 'shop.example.org', same_site = 'lax' })
--> 'sid=abc; Domain=shop.example.org; Path=/; SameSite=Lax; Secure; HttpOnly'
```

Настройки — те же, что у одной куки, и `key`. Заданное у куки главнее
настроенного, даже когда это `false`: `secure = false` — ответ, а не его
отсутствие.

- **Настройка проверяется сразу и бросает исключение**, а не возвращает
  отказ: опечатка обязана уронить запуск узла, а не каждый его ответ.
  Проверяются имена, роды и содержимое — путь, домен и срок теми же
  правилами, что и у отдельной куки. Ключ не показывается даже в отказе:
  отказ по настройкам уходит в журнал запуска целиком.

  ```lua
  cookie.configure({ htpp_only = true })   -- бросает: неизвестная настройка htpp_only
  cookie.configure({ same_site = 'maybe' })
  -- бросает: признак SameSite должен быть одним из: 'strict', 'lax', 'none', 'off', а не 'maybe'
  cookie.configure({ path = 'admin' })     -- бросает: путь куки должен начинаться с «/»: …
  cookie.configure({ key = '' })
  -- бросает: ключ подписи должен быть строкой длиной не меньше 1 знака, а сейчас 0 знаков
  cookie.configure({ key = 42 })
  -- бросает: ключ подписи должен быть строкой длиной не меньше 1 знака, а не присланным значением
  ```

  Упавшая настройка не действует: остаются прежние. Место в отказе —
  строка, которая позвала `configure` или `new`, а не строка внутри
  пакета: чинить надо там, и там же её ищут в журнале запуска.

  ```lua
  -- app.lua, строка 12
  cookie.configure({ path = 'admin' })
  -- бросает: app.lua:12: путь куки должен начинаться с «/»: …
  ```
- **Каждый `configure` начинает с умолчаний пакета**, а не с прошлой
  настройки: вызов `configure({ same_site = 'strict' })` после
  `configure({ domain = 'example.org' })` оставляет куки без домена.
  Настройки задаются одной таблицей.
- **Общий набор заводится заново после каждой настройки**: настройка,
  сделанная после первой куки, меняет поведение, а не остаётся словами.
  Сам набор отдаёт `cookie.default()`.

Отдельный набор со своими умолчаниями — `cookie.new(opts)`: те же
проверки, методы зовутся через двоеточие, и на общий набор он не влияет.

```lua
local admin = cookie.new({ path = '/admin', same_site = 'strict' })

admin:set('sid', 'abc')     --> 'sid=abc; Path=/admin; SameSite=Strict; Secure; HttpOnly'
admin:expire('sid')         -- та же кука с нулевым сроком на /admin
```

У набора есть `set`, `expire`, `sign`, `unsign`, `parse`, `parse_set`,
`jar` и `status`.

`status()` показывает действующие настройки — кроме ключа: состояние
читают и журнал, и панель, и человек через плечо. Видно лишь то, что ключ
задан:

```lua
cookie.status()
--> { path = '/', domain = 'example.org', secure = true, http_only = true,
--    same_site = 'strict', partitioned = false, signed = true }
```

### Подпись: `sign` и `unsign`

Кука лежит у пользователя, и он волен её переписать: `admin=0` меняется
на `admin=1` в любом браузере за пять секунд. Подпись не прячет значение,
но делает его неизменяемым — без ключа подпись к подменённому значению
не собрать:

```lua
cookie.configure({ key = 'секрет' })

local signed = cookie.sign('42')      --> '42.l5ssuE_N2c469eeChsL3PbkCxn1o7ZKckWO7hj-aMpA'

cookie.unsign(signed)                 --> '42'
cookie.unsign('43' .. signed:sub(3))  --> nil, 'подпись значения не сошлась: значение переписано или ключ не тот'
cookie.unsign('42')                   --> nil, 'в значении нет подписи: она отделяется точкой в конце'
cookie.unsign(nil)                    --> nil, 'подписанное значение должно быть строкой, а не nil'
```

- Подпись — HMAC-SHA256 в base64url без набивки, через точку после
  значения. Простой хеш `sha256(key .. value)` не годится: его наращивают
  с хвоста, не зная ключа. Граница — последняя точка: в base64url точек
  нет, а в значении они могут быть, и `a.b.c` подписывается и открывается
  как любое другое.
- Сверка идёт за постоянное время: обычное сравнение строк выдаёт по
  времени, сколько первых знаков совпало, и подпись подбирается по одному
  знаку за раз.
- Ключ на месте главнее настроенного: `cookie.sign('42', key)`,
  `cookie.unsign(text, key)`.
- **Без ключа `sign` и `unsign` бросают**: подпись пустым ключом —
  не подпись, а её вид, и забытый ключ надо заметить при первом же
  запуске. Место в отказе — строка, которая позвала подпись.

  ```lua
  -- app.lua, строка 7
  cookie.new():sign('42')
  -- бросает: app.lua:7: подписать куку нечем: задайте ключ настройкой key
  ```

- Подпись — не шифрование: значение видно. Прятать надо не подписью,
  а тем, чтобы в куке лежал опознаватель, а не сами данные.

### Чужой `Set-Cookie`: `parse_set`

`cookie.parse_set(text)` разбирает один заголовок `Set-Cookie`
по алгоритму RFC 6265 (5.2), который нарочно мягче грамматики: серверы
ставят пробелы там, где грамматика их запрещает.

```lua
cookie.parse_set('sid="a b"; Expires=Sun, 06 Nov 1994 08:49:37 GMT; Domain=.Example.ORG; '
    .. 'Path=/admin; Secure; HttpOnly; SameSite=Strict; Max-Age=60')
--> { name = 'sid', value = 'a b', quoted = true, expires = 784111777, max_age = 60,
--    domain = 'example.org', path = '/admin', secure = true, http_only = true,
--    same_site = 'strict', partitioned = false }

cookie.parse_set('Secure')   --> nil, 'в заголовке Set-Cookie нет пары «имя=значение»'
cookie.parse_set(nil)        --> nil, 'заголовок Set-Cookie должен быть строкой, а не nil'
```

- Дата читается во всех трёх видах — `Sun, 06 Nov 1994 08:49:37 GMT`,
  `Sunday, 06-Nov-94 08:49:37 GMT` и `Sun Nov  6 08:49:37 1994` — одним
  разбором по лексемам (RFC 6265, 5.1.1). Двузначный год 70—99 читается
  как 1970—1999, 00—69 — как 2000—2069; год раньше 1601-го, секунда 60
  и 31 февраля — не дата.
- Непонятные дата, `Max-Age`, путь без ведущей косой и пустой домен
  пропускаются, а кука остаётся: сервер с кривыми часами не должен лишать
  клиента сессии. Незнакомый атрибут тоже пропускается. Из повторённых
  атрибутов действует последний понятый.
- Имена атрибутов читаются без регистра; ведущая точка домена снимается,
  домен приводится к нижнему регистру.
- `SameSite` запоминается только словами `strict`, `lax` и `none`.
  Незнакомое слово не пропускается, а сбрасывает признак: браузер сводит
  его к умолчанию, и записывать то, чего сервер не присылал, незачем.
- Кавычки со значения снимаются, но поле `quoted` запоминает, что они
  были: хранилище вернёт значение серверу точно таким же.

### Хранилище для исходящих запросов: `jar`

Клиент, ходящий к чужому серверу, обязан вести себя как браузер: взять
куки из ответа, запомнить и приложить к следующему запросу — но только
к тому, которому они предназначены.

```lua
local jar = cookie.jar()

jar:put('https://example.org/login', 'sid=abc; Path=/; Secure; HttpOnly')   --> true
jar:put('https://example.org/a/b', 'theme=dark')                             --> true
jar:put('https://evil.org/', 'sid=x; Domain=example.org')
--> false, 'узел «evil.org» не входит в домен «example.org»: такую куку он ставить не вправе'

jar:header_for('https://example.org/a/c')   --> 'theme=dark; sid=abc'
jar:header_for('http://example.org/a/c')    --> 'theme=dark'
jar:header_for('https://other.org/')        --> nil
```

`jar:put(url, header)` — `true` либо `false, err`; `jar:header_for(url)` —
значение заголовка `Cookie`, `nil`, если слать нечего, либо `nil, err`
на негодный адрес. Адрес нужен полный, со схемой и узлом: без схемы нечем
ответить, защищено ли соединение.

```lua
jar:put('/login', 'sid=abc')
--> false, 'адрес «/login» не годится: кука знает, кому принадлежать, только по полному адресу
--  со схемой и узлом — вроде https://example.org/path'
```

Отбор — по RFC 6265:

- **Домен.** Кука без `Domain` принадлежит ровно поставившему её узлу
  и не уходит ни на один поддомен. С `Domain` она уходит на узел домена
  и все его поддомены — но только если узел, приславший её, сам входит
  в этот домен. Домен без точки (`Domain=org`) — зона целиком, отказ;
  публичный суффикс вроде `co.uk` — тоже, если на узле есть список
  (см. «Публичные суффиксы»). Узел-адрес (`10.0.0.1`, `[::1]`) получает
  куку только сам: у адреса суффикс `0.0.1` — не домен, а обрезок числа.
- **Путь.** Без `Path` путь куки — каталог запроса: ответ на `/a/b/c`
  ставит куку на `/a/b`. Путь сверяется по каталогам: кука на `/foo`
  доходит до `/foo` и `/foo/bar`, но не до `/foobar`.
- **`Secure`.** Такая кука уходит только по `https` и `wss` и только
  их ответом ставится; схема сверяется без регистра (см. «Открытый
  канал и `Secure`»).
- **Срок.** `Max-Age` старше `Expires`: он задан длительностью и не зависит
  от того, насколько разошлись часы сервера и клиента. `Max-Age` ноль
  и меньше или дата из прошлого — кука не уходит ни разу. Ни того
  ни другого — кука живёт, пока живёт хранилище. Протухшая выбрасывается
  при следующем отборе, а не просто пропускается.
- **Замена.** Куку опознаёт тройка «имя, домен, путь»: новая такая же
  заменяет прежнюю на её месте, `sid` на `/a` и `sid` на `/a/b` живут
  рядом.
- **Порядок.** Впереди куки с более длинным путём, среди равных —
  появившиеся раньше.

`jar:size()` — сколько кук лежит, вместе с ещё не выброшенными
протухшими; `jar:clear()` забывает всё — другого способа выйти из чужой
сессии у клиента нет. Каждое `cookie.jar()` — своё пустое хранилище:
умолчания настроек пакета ему не передаются, они про куки, которые ставим
мы, а хранилище держит чужие.

`HttpOnly`, `SameSite` и `Partitioned` хранятся, но на отбор не влияют:
первый запрещает отдавать куку сценарию на странице, а здесь всё
происходящее и есть HTTP-запрос; для двух других у клиента нет ни «сайта»,
ни окружения, с которыми их сверять.

### Открытый канал и `Secure`

Ответ по `http` или `ws` мог прийти не от сервера, а от посредника,
который сидит на сети. Поэтому хранилище держит поверх RFC 6265 два
правила черновика RFC 6265bis (5.7):

```lua
local jar = cookie.jar()

jar:put('http://example.org/', 'sid=planted; Secure')
--> false, 'кука «sid» с признаком Secure пришла по открытому каналу: её мог подложить посредник,
--  и хранилище её не берёт'

jar:put('https://example.org/', 'sid=real; Secure; Path=/login')   --> true
jar:put('http://example.org/', 'sid=planted; Path=/login/en')
--> false, 'кука «sid» пришла по открытому каналу, а защищённая с тем же именем уже лежит:
--  открытый ответ не вправе ни заменить её, ни заслонить'
jar:put('http://example.org/', 'sid=open; Path=/')                 --> true
jar:header_for('https://example.org/login/en')                     --> 'sid=real; sid=open'
```

- **Кука с `Secure` из открытого канала не берётся.** Хранилище отдало
  бы её настоящему серверу по защищённому каналу, и клиенту досталась бы
  подложенная сессия.
- **Открытый ответ не заменяет и не заслоняет защищённую куку** с тем же
  именем. Заслонить — значит поставить куку, которая поедет впереди
  защищённой: домен одной входит в домен другой, в любую сторону, а путь
  новой лежит на пути защищённой или глубже. Путь короче законен: там,
  где едет защищённая, такая кука едет после неё. Протухшая защищённая
  кука ничего не держит.
- Ответ по `https` и `wss` ставит и заменяет любые куки.
- Защищённым каналом считаются только `https` и `wss`, и `localhost`
  не исключение. Куки набора ставятся с `Secure` по умолчанию, поэтому
  клиент, который ходит к своему приложению по `http://127.0.0.1`,
  получит отказ на каждую такую куку — обратно по открытому каналу
  она всё равно бы не уехала.

### Приставки в хранилище

Сервер, читающий `__Host-sid`, верит имени на слово: эту куку поставил
сам узел, на весь узел и по защищённому каналу. Кука, пришедшая
с приставкой, но без обещанного, сделала бы это слово ложью: соседний
поддомен поставил бы `__Host-sid` на весь домен, и сервер принял бы
подложенную сессию за свою. Поэтому хранилище держит правила приставок
черновика RFC 6265bis (5.7):

```lua
local jar = cookie.jar()

jar:put('https://evil.example.org/', '__Host-sid=x; Secure; Path=/; Domain=example.org')
--> false, 'кука «__Host-sid» пришла с атрибутом Domain, а приставка __Host- обещает куку одного узла:
--  хранилище такую куку не берёт'
jar:put('https://example.org/', '__Host-sid=x; Secure')
--> false, 'кука «__Host-sid» пришла без Path=/, а приставка __Host- обещает куку на весь узел:
--  хранилище такую куку не берёт'
jar:put('https://example.org/', '__Secure-id=y')
--> false, 'кука «__Secure-id» пришла без признака Secure, а приставка __Secure- обещает его:
--  хранилище такую куку не берёт'

jar:put('https://example.org/login', '__Host-sid=abc; Secure; Path=/')   --> true
jar:header_for('https://example.org/api')                               --> '__Host-sid=abc'
jar:header_for('https://sub.example.org/')                              --> nil
```

- **`__Secure-`** — только с `Secure`, и значит, только из защищённого
  ответа: из открытого канала `Secure` не берётся (см. «Открытый канал
  и `Secure`»). Домен и путь эта приставка не трогает.
- **`__Host-`** — с `Secure`, без `Domain` и с `Path=/`, названным самим
  сервером. Путь по умолчанию не в счёт, даже когда он `/`: ответ
  на `/` без атрибута `Path` обещанного не называл. `Path` не с косой
  разбор пропускает, и такая кука тоже получает отказ — строже
  черновика, который подставил бы путь по умолчанию.
- Узел, чьё имя само стоит в списке суффиксов, вправе назвать себя
  в `Domain`: кука остаётся кукой одного узла (см. «Публичные
  суффиксы»), и обещание `__Host-` она держит.
- Приставка узнаётся без регистра: `__HOST-sid` несёт те же обещания,
  что и `__Host-sid`. Сервер, сравнивающий имена кук без регистра,
  прочёл бы одну как другую, и подложенная кука обошла бы проверку
  другим написанием.
- Кука, нарушившая заодно правило открытого канала, получает отказ
  за канал: в черновике он проверяется раньше приставок.

### Публичные суффиксы: libpsl

По одному имени зону от домена не отличить: `co.uk` и `example.org`
устроены одинаково, и узел `evil.co.uk` с `Domain=co.uk` правило
RFC 6265 (5.1.3) выполняет. Отличает их только список публичных
суффиксов (publicsuffix.org), и хранилище берёт его у системной
библиотеки libpsl, если она есть на узле:

```lua
local jar = cookie.jar()

jar:put('https://evil.co.uk/', 'sid=x; Domain=co.uk')
--> false, 'домен «co.uk» — публичный суффикс: под ним живут чужие друг другу узлы, и кука ушла бы ко всем'

jar:put('https://github.io/', 'sid=abc; Domain=github.io')   --> true
jar:header_for('https://github.io/')                          --> 'sid=abc'
jar:header_for('https://evil.github.io/')                     --> nil
```

- Узел, чьё имя само стоит в списке, свою куку поставить вправе, но она
  остаётся кукой одного этого узла (RFC 6265, 5.3, шаг 5): его поддомены
  принадлежат чужим друг другу владельцам.
- Своей копии списка у пакета нет: в списке около десяти тысяч записей,
  и меняется он много раз в год — копия внутри пакета устаревала бы
  молча. libpsl сама выбирает свежее из встроенного в неё списка
  и системного файла, который обновляется отдельно от неё.
- Библиотека ищется через `ffi.load` по имени `psl`, затем по soname
  `libpsl.so.5`. В Debian и Ubuntu это пакет `libpsl5` (`libpsl5t64`),
  его тянет libcurl. Нет библиотеки — нет и ответа, и хранилище остаётся
  при правиле «в домене хотя бы одна точка».
- Ответ запоминается на процесс, и отсутствие тоже: иначе узел без libpsl
  искал бы её на диске на каждую куку с `Domain`. Библиотеку, поставленную
  после запуска, узел увидит после перезапуска.
- Точка в конце домена (`co.uk.`) снимается перед вопросом к списку:
  это тот же узел, а сама libpsl такую запись суффиксом не считает.

Есть ли список на узле, отвечает сам модуль:

```lua
require('tnt.cookie.suffix').is_public('co.uk')   --> true; nil — списка на узле нет
```

### Подмена часов и списка в проверках

Срок в хранилище меряется стенными часами `tnt-clock`, и они — внешняя
зависимость модуля `tnt.cookie.jar`: проверка подменяет их через
`_set_source`, и час жизни куки проходит мгновенно.

```lua
local source = require('tnt.cookie.jar')
local now = 1700000000

source._set_source({ clock = { realtime = function() return now end } })

local jar = cookie.jar()
jar:put('https://example.org/', 'sid=abc; Max-Age=60')

now = now + 59
jar:header_for('https://example.org/')   --> 'sid=abc'
now = now + 1
jar:header_for('https://example.org/')   --> nil

source._set_source(nil)                  -- настоящие часы обратно
```

Подменить можно только `clock`; незнакомое имя бросает сразу — подмена,
промахнувшаяся именем, иначе ничего не подменила бы.

Список суффиксов подменяется так же — загрузкой библиотеки у модуля
`tnt.cookie.suffix`. Проверке, которой нужен узел без libpsl, хватит
загрузки, которая ничего не находит:

```lua
local suffix = require('tnt.cookie.suffix')

suffix._set_source({ load = function(name) error(name .. ': нет такой библиотеки') end })
suffix.is_public('co.uk')   --> nil

suffix._set_source(nil)     -- настоящая загрузка обратно
```

Двойник со своим списком — таблица с функциями `tnt_cookie_psl_latest`
и `tnt_cookie_psl_is_public`: под этими именами модуль объявляет символы
libpsl. Ответ запоминается на загрузку, поэтому каждая подмена новой
функцией спрашивает библиотеку заново.

## Чем пришлось поступиться

**Отказ настройки — исключение.** `configure`, `new` и подпись без ключа
бросают, а не возвращают `nil, err`: ошибка в настройке — своя, а не
чужая, и заметить её надо при запуске.

**Список публичных суффиксов — только с libpsl.** Без неё `Domain=co.uk`,
выставленный узлом `evil.co.uk`, проходит проверку RFC 6265 и расходится
по всей зоне: домен без единой точки отвергается, но это отсекает только
`Domain=com`. С ней список свеж настолько, насколько свежа система: зону,
заведённую после её обновления, хранилище не знает. Библиотеку,
поставленную после запуска, узел увидит только после перезапуска.

**Из черновика RFC 6265bis взяты только правила открытого канала
и приставок.** В остальном хранилище держится RFC 6265. Порт в отбор
не входит (RFC 6265, 8.5): кука с `example.org:8443` уходит
и на `example.org:9000`, и `__Host-` здесь не исключение — приставка
держит куку при узле, но не при порте.

**Хранилище живёт в памяти процесса и не ограничено.** Числа кук на домен
и их размера никто не считает: сервер, поставивший тысячу кук, получит
тысячу записей. Протухшие выбрасываются при отборе.

**`Set-Cookie` разбирается по одному заголовку.** Склеивать несколько через
запятую нельзя: запятая стоит внутри даты («Sun, 06 Nov»), и разрез
пришёлся бы посередине срока.

**Срок меряется стенными часами** — иначе не с чем сравнить чужую дату.
Плата: перевод часов назад продлевает жизнь уже сохранённым кукам.

**Кавычки со значения снимаются**, хотя RFC 6265bis велит считать их
частью значения. Расхождение намеренное: иначе подпись не сойдётся
ни у кого, кто прислал значение в кавычках.

**Ключ подписи один.** Смена ключа разом делает негодными все выданные
подписи. Переходное время устраивается руками — ключ на месте главнее
настроенного:

```lua
local sid = cookie.unsign(sent) or cookie.unsign(sent, old_key)
```

## Проверки

Проверки лежат в `test/` и идут на luatest: `.rocks/bin/luatest test/`.
Модули пакета берутся из исходников, зависимости — установленными.
Исходники грузятся заново перед каждой проверкой: и подменённые часы,
и настройки общего набора живут в модулях.

Часы хранилища подменены двойником, который двигает сама проверка:
кука на минуту умирает ровно на шестидесятой секунде, и проверка этого
не ждёт. Отказы сверяются текстом, собранные заголовки — целиком,
с порядком атрибутов.

libpsl в проверках — двойник со своим списком суффиксов: проверки
хранилища не зависят от того, стоит ли библиотека на машине и насколько
свеж её список. Сами объявления FFI сверяет живая проверка
`suffix_live_test.lua` на системной libpsl; нет её — проверка
пропускается. Место броска сверяется вызовом из чанка с выдуманным
именем файла: в отказе обязаны стоять это имя и строка вызова.

Точный вид подписи закреплён проверкой. Сменить способ подписи молча —
значит разом разлогинить всех, у кого кука уже лежит, и такой промах
должен ловиться проверкой, а не жалобами.

Покрытие строк — 100 %, убитых мутантов — 100 % (181 проверка,
631 мутант в восьми модулях), правил исключения мутантов нет.
